## 0. 背景（30 秒版）

作者在 `fictionforge` 仓库里做了一个基准 **CanonBench**：测「长篇叙事一致性」——
12 章的小说里，第 2 章死掉的人会不会在第 4 章端着水走过来；第 5 章才该知道的事
会不会第 3 章就说了出来。

做法：判定器（纯函数、零 LLM、可审计） + 确定性合成宇宙（同 seed 逐字节相同） +
三档 harness 消融跑批（裸写 / 注入上下文 / 满配门禁），把「模型能力」与「工程管线」
的贡献分开。首期测了 3 家模型 × 3 档 × 6 章，结果与复现协议都在仓库里。

**尚未发布正式版，也未投稿。请你先把它审一遍。**

你要审的不是「这个项目好不好」，而是**它自称的那些保证是不是真的**。

## 2. 审计线

### A. 判定器与 ground truth

1. **「判定器零 LLM、可审计」**——`bench/judges/` 有没有任何隐藏依赖（时间、随机、网络、环境）？
   同输入两次运行是否逐字节一致？
2. **「合成宇宙同 seed 逐字节可复现」**——跑两次 `generate(seed=42, chapters=6)` 比对；
   `BENCH_PROTOCOL.md` 里的 sha256 表（universe.json / novel_config.json / 真相表.json）能否复算命中？
3. **「不变量自检能失败」**——`generator.invariants()` 的每一条，人为注入一次违反，
   是否真会被抓到？有没有恒真的不变量（无论宇宙怎样都返回「无违规」）？
4. **死人复活判据的边界**——作者声称「遗物/回忆性指称不算复活」（`_MEMORIAL_RE` + 领格豁免 +
   活动动词窗口）。请构造反例：**真复活被漏掉**、**非复活被误报**，各至少要一条。
   作者已在 docstring 里承认一类已知漏报（比喻词豁免），你要审的是：**还有没有别的**。

### B. 指标与报表口径

5. **「门禁贡献用配对测量」**——`gate_contribution` 只统计同一次 full 运行内修前→修后。
   造一组 run 检验：`post_fix == []`（门禁全擦干净）的 run 会不会被漏统计？
6. **「未完成/部分完成的 run 不进汇总」**——`aggregate_by_model` 的剔除规则与
   `render_markdown` 脚注是否一致？缺 `violations.json` 的残缺 run 会显示成几条违反？
7. **「密度与绝对数成对」**——有没有哪个输出路径只给了密度或只给了绝对数？
8. **页面与文档同源**——`bench/report/html.py` 现算的数字与
   `docs/canonbench-results-v2.md` / writeup §8 的表是否逐格一致？
   抗刷分基线住在 `bench/attacks/attacks.py`（`BASELINE_TEXT`）——三处是否真的同一份输入？

### C. 跑批与复现协议

9. **「clone 后可离线重判」**——照 `README.md` 的「30 秒跑一遍」执行；
   再用 `bench.results.v2` 的正文重判一次（零 LLM），判决是否与入库的 `violations.json` 逐条一致？
10. **「续跑只跳过真完成的 run」**——`run_one` 的 skip 条件是否真的要求「无错误且章数齐」？
    造一个带 errors 的残缺 run，续跑会 redo 还是静默跳过？
11. **「瞬态错误退避重试」**——重试环会不会吞掉不可重试的错误（400/402/422）？
    有没有可能把一次真失败伪装成成功？

### D. 真实文本校准（本次重点，方法学最脆弱的一环）

12. **「注入法不需要人工标注」**——请审这个论证：正例（真违反）与诱饵（不该报的孪生句）
    只差一个词，插进同一份真实文本的同一位置，于是「抓到/没抓到」只可能来自判据本身。
    **这个推理有什么漏洞？** 有没有可能「抓到了正例」其实是别的原因（例如注入句本身
    改变了段落结构/长度/相邻引号）？
13. **「差分测量与信号量测量」**——作者修过两个测量坑（真实文本固有命中会淹没诱饵判定；
    禁词按章聚合时注入第二次不增加条数）。请验证这两个修法本身是否正确、
    以及**还有没有第三个同类坑**。
14. **「38k 字真实散文上状态类判据零误报」**——注意：这 38k 字里
    公开语料只有 3.2k（`novels/静默轨道/chapters/`），其余是**私有稿，不入库、不可复核**。
    作者把它写进了对外文档。**这条结论的可验证性值多少？应该怎么写才算诚实？**

### E. 请你反驳作者的方法学结论（必答，写进「最脆弱」一节）

作者在 `docs/canonbench-writeup.md` §10 与 `docs/canonbench-calibration.md` 末尾列了
「诚实边界」。请**逐条判断它是真边界还是免责话术**，并至少反驳一条：

- k=1 只能说方向，精确归因需 k≥3
- 合成宇宙 ≠ 真实长篇（模板重复度高，本质是校准判定器的工具）
- 密度指标永远可被加字稀释，绝对数只是缓解不是解决
- 判定器口径绑定中文 / 第三人称 / 特定引号约定，换负载要改判据
- 「比喻词豁免」的取舍：作者实测收窄后误报 4 : 真阳性 0，因此保留宽豁免——
  这个取舍判断成立吗？k=1 之外还有没有别的解释？
- 注入法只覆盖可注入判据；账本级判据（时间线倒退、物品双持有）不在此列

**另外**：作者自己做过一轮三方审计（代码审查 / 文档数字对账 / 仓库卫生），
结果记在 `CHANGELOG.md` 的 v0.4.1 段。**请审「那一轮审计的结论本身」**：
它声称修掉的三个报表缺陷，回归测试是否真的能失败（把修复回滚，测试会不会红）？

## 3. 作者已知的弱项（不必重复发现，但请审「这份清单全不全」）

- k=1（单次采样），档位差值含采样噪声
- 合成宇宙模板化，文本重复度高
- 知识边界的语义判定（清单式 LLM judge + Kappa）**未实装**
- 术语轰炸无专门判据（它不是重复）
- 真实文本校准的私有语料不可复核（见 D14）

   并注明**你是怎么查出来的**（跑了什么命令、看到什么）。没复现的写「推理，未复现」。
2. **最脆弱一环**：只能写一条。写你认为最可能让这个基准在同行面前站不住的那一处。
3. **附录：你推翻了什么**——包括你一开始怀疑、查完发现作者是对的那些（同样有价值）。
4. 最后一行给出你实际执行过的命令清单。

不要报风格、命名、注释问题。只报**会导致错误结论或掩盖错误**的问题。
