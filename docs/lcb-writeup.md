# 长程一致性怎么测：一个能自动判定的基准（LCB）

> 草稿 v3 · 2026-09-27。可发知乎 / 掘金 / 公众号 / GitHub Discussions。
> 配套代码：`bench/`（判定器 + 合成宇宙 + MCP server），`docs/BENCH_PLAN.md`（实施计划）。
> 命名 LCB 为占位，未定稿。

---

## 一、问题：长程一致性是 agent 的真问题，但缺一把对的尺子

让模型写一部 12 章的小说，它会干这些事：

- 第 2 章死掉的角色，第 4 章又端着水走过来
- 第 5 章才该知道的事，第 3 章就说了出来
- 第 1 章埋的细节（一道疤、一笔债），第 10 章回收时对不上

这些不是文笔问题，是**长程状态追踪**问题——和 agent 的记忆、上下文腐坏、知识边界是同一类。

先说清它和现有长上下文评测的区别。**大海捞针（NIAH）、RULER、LongBench 这一系测的是检索**：埋一个事实，提问，看模型能不能捞出来。那是「按题作答」。而写小说时的失败面完全不同——模型在**无题自由生成**，没人提醒它「注意第 2 章那个死人」，它得自己不漏出不该知道的事、不违反已知状态。检索满分和生成中不漏，是两种能力。据我所知，以**自动判定**为核心、面向生成一致性的公开基准还很少——这正是本文要补的位置（欢迎指正我没看到的同类工作）。

所以我做了 **LCB（Long-horizon Consistency Bench）**：一个**有自动判定器**的长程叙事一致性基准。它的定位不是「评测小说写得好不好」（那需要审美判断），而是**只测能自动判定的那部分**——状态、知识、时间线、约束。审美留给人类，状态留给机器。

## 二、设计五原则

| 原则 | 具体含义 |
|---|---|
| **自动判定** | 人手不进场。否则不可规模化，也不算基准 |
| **可复现** | 种子 / 模型版本 / 判定器版本 / judge prompt 版本全部入 manifest，任何数字可追到一次运行 |
| **可归因** | 同一模型跑「裸 harness vs 满 harness」，把**模型能力**与**工程 harness**分开 |
| **抗刷分** | 基准自带攻击自测（注水 / 重复 / 术语轰炸），并公示结果——含尚未通过的自测 |
| **离线可测** | 判定器核心纯函数化，单元测试**零 LLM、零网络**；LLM 判定走可注入后端 |

最后一条尤其重要：一个评测项目如果自己的判定器不可测，就没有资格评测别人。

## 三、测什么：四类可判定探针

| 类型 | 埋法 | 判定方式 |
|---|---|---|
| **知识边界** | 真相表标「谁在第几章知道什么」 | 角色提到此刻不该知道的信息 |
| **状态一致** | 死亡 / 物品 / 位置 / 时间线入状态账本 | 死人复活、物品瞬移、天数倒流 |
| **上下文腐坏** | 第 1 章埋无关细节 | 第 N 章能否正确回收，按距离画衰减曲线 |
| **约束遵守** | 禁词 / 篇幅 / 人称 / POV | 机械可数 |

其中**知识边界**是这套基准的前置条件——要测它，你得先有「真相 / 知识」两层建模（作者维护权威事实表，逐角色维护已知集合）。据我观察，多数自建评测缺这一层，这也是本文方法难被直接照抄的地方。

## 四、判定器：机械优先，清单式 LLM 兜底

**第一层：机械判定（确定性、免费、可审计）**

禁词计数、段落长度、篇幅偏差、POV 越界、人称混用、死人复活、时间倒流、物品双持有——纯函数判定，零 LLM 调用，单元测试可精确断言。

**第二层：清单式 LLM 判定（只跑语义部分）**

知识边界这种需要理解语义的，不让 judge 自由打分，而是把「该角色此刻的已知集合」变成 **checklist 逐项判定是/否**。清单式判定的一致性远高于自由评分——这与业界趋势一致（截至撰写：Arena-Hard v2、WildBench 一系走向清单化；MT-Bench 报告过 judge 与人类标注的一致率；AlpacaEval 2.0 用 length-controlled 指标专治长度偏差）。

**准入门槛（设计，尚未执行）**：judge 与人工标注的一致率（Kappa）达标才发版；judge 模型版本 + prompt 版本入 manifest。目前人工标注量：零——这是下一步的工作，不是已完成的声明。

## 五、归因：harness 三档消融（设计，未跑）

同一模型，跑三档：

```
bare   一个系统 prompt + 本章 spec              → 模型裸能力
mid    + 设定/状态/前文/知识边界注入             → 上下文工程的贡献
full   + 门禁 + 自动返修 + 状态回写              → 后处理门禁的贡献
```

为什么必须三档而不是两档：**门禁会字面上把违反改掉**（自动替换禁词、返修篇幅）。只跑「裸 vs 满」，你分不清改进是「上下文给对了」还是「门禁擦掉了」。三档让两者各领各的功劳——这就是评测岗位常说的「归因到模型能力 vs 工程 harness」。

（实测数字见 §9——两期跑批都验证了三档结构的必要性：门禁的贡献只有配对测量才量得准。）

## 六、合成宇宙：确定性 ground truth

基准的输入不能靠人写（不可规模化，也有版权问题）。所以：

```
seed → 一部可跑的合成小说包
        cast + 真相表（含 false 行=错误认识）+ 知识表（谁在第几章学到什么）
        + 分幕 + 章节 spec（含声明式状态：谁死、谁拿到什么）
```

**关键决策：生成器零 LLM，纯确定性。** 同 seed 落盘文件**逐字节相同**。理由：

1. 判定器需要 spec 结构精确可控
2. 基准的 ground truth 不能有随机性——否则「违反」的判定本身就不稳定

生成器自带**不变量自检**：事实引用存在、学习章号在范围内、终局真相不早于末章、**死者不得在死后获知信息或作为行动者出现**、至少一条 held-out 事实、每章恰一个 expanded 节、时间线单调。

**已知弱点，直说**：模板化生成的文本重复度很高（本质上是少量模板做槽位填充）。它现在的用途是**校准判定器**——ground truth 可控、违规可预知；要测模型在丰富真实文本上的表现，靠的是后续接入的真实内容包（in-the-wild 补充集），而不是把合成宇宙当终极负载。

## 七、自证：判定器抓出的第一批违规，来自我自己的数据

这是我最想讲的一段。

写完判定器后，我把它们包成 MCP server，接进 Claude Code 真跑了一遍完整流程（生成宇宙 → 查账本 → 查真相表 → 跑门禁）。

**结果：账本显示某个角色第 2 章死了，可第 3-6 章的「在场名单」里还有他。**

原因是我的**生成器**：每章描述模板都会提一句这个名字（「某某以前也问过同样的问题」），而账本把「名字出现」记为「在场」——于是我的 ground truth 自相矛盾。

第二个 bug 是同一轮抓出来的：章节描述里硬编码了「她」，而该 seed 的主角是男性。

两个 bug 都不是单元测试能发现的——**单测只能覆盖我预设的行为**，而「死后点名」「人称与配置一致」这种跨章节约束，得真跑一遍链路才暴露。

我做了两件事：
1. 修生成器（死后章节改用其他角色；人称按角色性别取）
2. **把这一类加进不变量自检**：死者不得在死后章节描述中被点名——并配了**阴性对照测试**（人为注入一次违规，断言必须被抓到）

值得说透的是顺序：不变量**不是设计出来的，是被 bug 逼出来的**。第一版不变量只查知识层，死后点名是翻车之后补的。阴性对照是防自欺的关键：不变量如果恒返回「无违规」，测试照样绿，但什么都没测到。

### 同一个教训的另一半：判定器也要用真实数据校准

第一次跑批（3 模型 × 3 档 × 6 章）我顺手抽查了生成稿的判定输出，结果是：

```
17 条违反 → 13 条是误报
```

三类误报，全是单测覆盖不到的：

| 误报 | 实例 | 病根 |
|---|---|---|
| 引文只在**行首**被识别 | `他说：“这箱子是我的，你少管。”` | 「旁白+对话」同行时，对话里的「我」被当成旁白第一人称 |
| 人称判据太天真 | `苏茜转身看他。` | 「他」指场上的另一个男性角色，而该角色的**名字**没出现在这句话里 |
| 相对时间被当绝对日期 | `搬盐的人，第二天就走了。` | 「第二天」是相对参照，被判成「日期倒退到第 2 天」 |
| 无引号直接引语被当旁白 | `苏茜说我没听说有这回事。` | 中文小说常用不加引号的引语，句中「我」被当成视角越界 |

修完之后同一批稿子：**17 条 → 4 条，且剩下 4 条全是真信号**（段落过长 / 篇幅不足 / 禁言词）。第四类最值得说：它不是实现 bug，是**语言习惯问题**——判据得懂中文小说怎么写对话，光靠正则不行。修法是收窄到「句首第一人称才算越界」，实测这批数据零误报。

为什么单测没抓到：**我构造 fixture 时，例句是自己想象出来的干净样本**——对话规规矩矩写在行首、代词都指主角、日期都是绝对天数。真实生成文本不长这样。修完之后，测试夹具直接采用真实误报的原文，这几类从此钉死。

这两段合起来是同一句话：**判定器和 ground truth 都必须被真实数据打一遍**。设计文档、单测、demo 都替代不了它。

## 八、抗刷分：三个攻击全打穿了密度指标（实测）

任何自动判定都会被针对性优化。所以基准要自带攻击自测——写攻击清单的第一天，它就先抓到了**我自己指标上的洞**，而且三个攻击**全部奏效**。

**洞的原理**：密度类指标 `违反数 / 字数 × 10000`，只要字数涨、违反数不涨，指标就变好。而"加字"是刷分者最廉价的操作。

实测（全部离线可复现，跑 `tests/test_attacks.py`；基线是一段 200 字、含 1 处禁词违反的文本）：

| 攻击 | 字数 | 绝对违反 | 违反/万字 | 密度变化 | 重复率 |
|---|---|---|---|---|---|
| 基线 | 200 | 1 | 50.00 | — | 0.00 |
| 注水 ×6（干净填充） | 1200 | 1 | 8.33 | **−83%** | 0.76 |
| 复制 ×4 | 803 | 1 | 12.45 | **−75%** | 0.72 |
| 术语轰炸（40 个设定词） | 320 | 1 | 31.25 | **−38%** | 0.09 |

三条结论，都和原计划的假设不同：

1. **注水有效**——计划里写的"注水不该改变分数"是错的，它能把密度刷低 83%
2. **复制也有效**——且比原以为的更隐蔽：我们的违反是**按章聚合**的（同一禁词在一章内算一条），所以复制不改变绝对数，只稀释密度
3. **术语轰炸同样有效**——原计划说"堆术语不该让分数上升"，实测它照样稀释 38%。**只要指标是密度，任何加字都稀释**，与内容有没有实质无关

**防线（已实现 + 待建）**：

- ✅ **绝对数与密度成对同报**——攻击对密度有效，对绝对数无效（表里三行都是 +0）
- ✅ **重复率判据**（`duplicate_ratio`）：去空白后逐字滑动 80 字窗口，统计重复窗口占比。抓住注水（0.76）与复制（0.72），且**不误报正常文本**（基线 0.00）。踩过两个坑：段落法对短段落瞎；固定步长会与重复周期错位而漏检
- ⚠️ **篇幅门禁**：拦 ±20% 之外的注水；门内仍有稀释空间，彻底解法是按固定长度窗口切片评测（待建）
- ❌ **术语轰炸没有专门判据**——它不是重复（重复率 0.09），只能靠篇幅门禁 + 绝对数兜。诚实地列为未解决

把没做成的也列出来，是因为**攻击清单里藏着指标定义的错误**。这一节不写，读者按我的旧版指标去刷分，一刷一个准。

## 十、边界与诚实清单

- **合成宇宙 ≠ 真实长篇**，且模板重复度高：判定器校准优先；真实负载靠 in-the-wild 补充集
- **LLM judge 不可靠**：机械层优先 + 清单式判定 + Kappa 准入（未执行）+ 判定器开源可审
- **判定器口径是中文、第三人称叙事、特定引号约定**（直角/弯引号对话识别）：换语言、换人称、换排版惯例都要改判定器——机械判定的普适性是假的，别骗自己
- **规模仍小**：两期受控跑批（3 厂商 × 3 档 × 6 章，k=1）已出数；语义判定（W4/W5）、
  k≥3 归因、阿里/Moonshot 补跑未做（见 `docs/BENCH_PLAN.md`）
- **不测审美**：写得好不好、有没有让人读下去的欲望，框架不碰——那是作者的事
