# LCB · 长程一致性基准 实施计划

> 建档 2026-09-22（v2，同日修订：judge/harness 设计定案、W6 确定性修正、加 W11/W12、时间盒）。
> **定位：有自动判定器的长程叙事一致性基准**——SWE-bench 之于代码，LCB 之于长篇状态。
> **LCB 的角色：评测 harness 作品的实体**——JD「设计评测任务 / 抗刷分 / 归因」四条职责的落地证据。
> 不是为了做个好用的排行榜，是为了让评审证据可复现。
> 落点：fictionforge 仓库内（`bench/`），复用 framework 资产；若长成独立产品再拆库。
> 服务对象：**同行评测人 / Agent 研究者**——他们要「哪个模型长程一致性更好、贵多少」。
>
> **非目标**：不做给人写作的产品化打磨；不做 UI；不追求覆盖全部叙事质量（只做**能自动判定**的那部分）。

**实现过程中被推翻的设计（都是真跑出来的，不是想出来的）**：

1. **harness 泄底**：终局真相的 category 是「世界真相」，被当客观设定注入第 1 章。
   修法 = 事实分三类语义（常识型 / 发现型 `reveal_chapter` / held-out 末章+1），
   并进不变量自检。教训：**ground truth 的语义分类不写清，harness 自己就会作弊**。
2. **密度指标可被加字刷低**：三个攻击实测分别把密度刷低 83% / 75% / 38%，
   而绝对数不动。原计划假设「注水/术语轰炸应无效」是错的。
   防线 = 绝对数成对 + 重复率判据 + 篇幅门禁（门内仍漏，切片评测待建）。
3. **续跑丢成本**：run.json 只在跑完时写，中途中断则已生成章节的 token/成本永久丢失。
   修法 = 逐章 `usage.jsonl`。
4. **输出格式要求缺失**：harness prompt 没写「不要标题/标记」，模型输出 markdown 标题
   污染字数统计（框架 gen.py 有，harness 漏了）。三档必须字面一致才公平。

## 一、设计原则（不可妥协的五条）

1. **自动判定**——人手不进场，否则不可规模化、不算基准
2. **可复现**——种子 / 模型版本 / 判定器版本 / judge prompt 版本全部入 manifest，任何数字可追到一次运行
3. **可归因**——harness 三档消融，把模型能力与工程 harness 分开（见 §三）
4. **抗刷分**——基准自带攻击自测（注水/重复/术语轰炸），并公示结果
5. **离线可测**——判定器核心纯函数化，单元测试**零 LLM、零网络**；LLM 判定走可注入后端，测试用录制回放

## 二、测量对象（探针四类）

| 类型 | 埋法 | 判定方式 | 依赖资产 |
|---|---|---|---|
| **知识边界** | 真相表标「谁在第几章知道什么」 | 角色提到此刻不该知道的信息 | `theory_of_mind.py` + 真相表 + info_gaps（已有半套） |
| **状态一致** | 死亡/物品/位置/时间线入状态账本 | 死人复活、物品瞬移、天数倒流 | spec + 真相表（确定性构建，见 W2） |
| **上下文腐坏** | ch1 埋无关细节（疤/债/承诺） | chN 能否正确回收，按距离画衰减曲线 | 探针生成器（新） |
| **约束遵守** | 禁词/篇幅/人称/POV | 机械可数 | `anti_ai_check` / `quality_check`（已有） |

**知识边界是护城河**：别人复刻要先有真相/知识建模这套。

## 三、harness 三档消融（归因轴，定案）

harness = 模型之外的全部工程脚手架。只跑两档分不清「上下文给对了」和「门禁擦掉了」：

| 档 | 里面有什么 | 没有什么 | 量的是什么 |
|---|---|---|---|
| **bare 裸** | 一个系统 prompt + 本章 spec | 无世界观/人设/前文/状态/门禁 | 模型**裸能力** |
| **mid 注入** | + bible（世界观/人设/写作法则）+ 章节状态 + 前文实稿 + 知识边界 info_gaps | 无门禁、无自动返修 | **上下文工程的贡献**（bare→mid） |
| **full 全套** | + anti-AI 门禁 + 自动返修 + 状态回写 + 漂移注记 | — | **后处理门禁的贡献**（mid→full） |

注：full 档的 auto-fix 会字面上改掉违反——报告时**同时报修前/修后违反率**，门禁的功劳单独记账。

## 四、judge 设计（定案）

- **v1 = 单 judge**：钉死模型版本 + temp=0 + prompt hash 入 manifest；与人类标注算 **Kappa**（50 条），Kappa 达标是判定器版本**发版准入门槛**
- **官方榜单发布时升级双 judge**（不同模型家族，防自我偏好），报一致率
- 判定 = **清单式**（逐 checklist 项是/否），不是自由打分——业界（Arena-Hard v2 / WildBench）验证一致性远高于自由评分
- 判定器开源可审；机械层优先（免费、确定性），语义判定只跑清单项（每章成本 ≪ 生成本文）

## 五、模块划分

```
bench/
  contracts.py      数据契约（manifest / violation / probe / version schema）—— 地基
  universe/         ① 合成宇宙生成器（纯确定性 seeded → 真相表 + 知识表 + 弧 + spec）
  probes/           ② 探针生成（知识边界 checklist + 腐坏埋点）
  judges/
    mechanical.py   ③a 确定性判定（人称/禁词/名字/时间线/死人/篇幅）
    semantic.py     ③b 清单式 LLM 判定，JudgeBackend 协议可注入
  state/            ④ 状态账本（从 spec + 真相表确定性构建）
  runner/           ⑤ 跑批编排（模型 × harness 三档 × 种子 × k 次）
  report/           ⑥ 指标（违反率/CI/pass^k/衰减曲线/成本）
  attacks/          ⑦ 抗刷分自测（注水/重复/术语轰炸）
  leaderboard/      ⑧ 榜单生成 + 复现协议
tests/              fixture 驱动单元测试（零 LLM）
```

## 六、工作项拆分

每项含：输入 / 输出 / 验收 / **单元测试** / 量级。

### W0 · 数据契约（地基）
- 输出：`contracts.py`——`RunManifest` / `Violation` / `ProbeSpec` / `BenchVersion` schema + 校验 + schema 导出
- 验收：下游模块只通过契约交换数据
- **单测**：序列化↔反序列化往返、必填缺失报错（报字段名）、枚举封闭（未知值报错）、版本字段必填、confidence 边界 [0,1]
- 量级：0.5 天

### W1 · 机械判定器（先出数字）
- 输入：正文 + spec（禁词表/人称/POV/篇幅）
- 输出：`Violation[]`（type=constraint，detector=mechanical）
- 验收：对现有 ch1/ch2 草稿跑出第一个违反率数字
- **单测**：fixture 正反例各 ≥3（人称混用/禁词/超篇幅/POV 越界），期望违反集精确相等；空文本/单句/超长边界
- 量级：1 天

### W2 · 状态账本（确定性构建）
- 输入：**spec + 真相表**（不解析 章节状态.md 散文——那是 spec 推断文本，脆弱）
- 输出：结构化 `StateLedger`（角色生死/位置/持有物/时间线，按章索引）
- 验收：从现有 ch1-3 spec 构建账本，diff 可读
- **单测**：spec fixture → 期望账本结构；时间线单调性正反例；同名角色消歧
- 量级：1.5 天

### W3 · 机械状态判定
- 输入：正文 + `StateLedger`
- 输出：`Violation[]`（type=state）
- 验收：ch1/ch2 出状态违反数（预期 0，阴性对照）
- **单测**：「死人复活」「物品瞬移」「时间倒流」fixture 各 ≥2 例命中；**合法回忆/闪回不误报** ≥2 例
- 量级：1 天

### W4 · 探针生成器
- 输入：真相表 + 知识表 + 章节索引
- 输出：`ProbeSpec[]`——(a) 知识边界 checklist，(b) 腐坏埋点/查询对
- 验收：现有真相表生成 ≥20 条探针，人工过一遍无荒谬项
- **单测**：真相表 fixture → 期望 checklist（集合相等）；`false` 行（B 型反转素材）不进「已知」；跨章知识增量正确累积
- 量级：1.5 天

### W5 · 语义判定器（清单式）
- 输入：`ProbeSpec[]` + 正文
- 输出：`Violation[]`（type=knowledge_boundary / rot，带 confidence）
- 验收：ch1/ch2 出知识边界违反数；人工标 50 条 **Kappa 达标**（发版门槛）
- **单测**：`JudgeBackend` 协议 + `FixtureJudge` 回放；prompt 组装纯函数测试（清单项逐条入 prompt、无自由评分指令）；Kappa 计算器（已知混淆矩阵 → 期望值）
- 量级：2 天

### W6 · 合成宇宙生成器（纯确定性）
- 输入：seed
- 输出：真相表 + 角色 + 知识表 + 弧 + spec——**零 LLM**（模板化生成；自产 spec，不接 spec_builder 的 LLM 路径——判定器需要 spec 结构精确可控）
- 验收：**同 seed 逐字节相同**；不同 seed 出不同宇宙；LLM 只用于跑批生成正文（固定 temp + prompt hash 入 manifest）
- **单测**：同 seed 幂等（字节级）；知识分配无矛盾（角色不能开头就知道终局真相）；弧结构合法
- 量级：2 天

### W7 · 跑批 runner
- 输入：宇宙 + 模型路由 + **harness 三档**（bare/mid/full）× k 次
- 输出：`RunManifest[]` + 正文 + 成本 + **修前/修后违反率分开记录**
- 验收：一次无人值守跑完「3 模型 × 3 档位 × 1 宇宙」，产出可复现目录树
- **单测**：编排逻辑（矩阵展开/断点续跑/失败重试）mock 测；manifest 字段完整性（模型/temp/prompt hash/档位）
- 量级：1.5 天

### W8 · 指标与报告
- 输出：每万字违反率、自助法 CI、pass^k、腐坏衰减曲线、成本-质量散点、**三档归因表**
- **单测**：指标计算器（已知输入 → 期望值）；bootstrap 固定种子可复现；pass^k 边界（k=1/全失败）
- 量级：1.5 天

### W9 · 抗刷分自测
- 输出：三攻击实验报告（注水/重复/术语轰炸）
- 验收：**注水不变分、重复降分、轰炸不升分**——任一失败 = 判定器有偏，回头修
- **单测**：攻击生成器纯函数测试（拉长 2× 语义不变：字数变/违反集不变）
- 量级：1 天

### W10 · 榜单与复现协议
- 输出：榜单页（静态）+ `docs/BENCH_PROTOCOL.md`（第三方提交协议）
- 验收：外人照协议本地复现榜单一行
- **单测**：榜单生成器（排序/并列）；协议命令 CI 跑通
- 量级：1.5 天

### W11 · writeup（G6）
- 输出：公开文章——「长程一致性基准的设计：判定器、消融与抗刷分」+ pipeline-experiments 消融史重述（假设→改动→度量→结论）
- 验收：发布 ≥1 篇；v5「坏例进 prompt 被克隆」= 判据污染案例写进去
- 量级：2 天（跟 M2 数字走）

### W12 · MCP server（G1 tool use 实锤）
- 输出：框架包成 MCP server——查章节状态 / 查真相表 / 生成草稿 / 跑门禁 = tools，Claude Code 直接驱动
- 验收：Claude Code 里真实调用 ≥4 个 tool 完成一次「查状态→生成→门禁」流程
- **单测**：tool handler 纯函数测试（入参校验/返回结构）
- 量级：2 天

## 八、风险与诚实边界

| 风险 | 处置 |
|---|---|
| 合成宇宙 ≠ 真实长篇 | 附真实内容包做 in-the-wild 补充集（**私有内容包不进公开 repo**，bench 只接路径参数） |
| LLM 判定不可靠 | 机械层优先 + 清单式判定 + Kappa 准入门槛 + 判定器开源可审 |
| judge 漂移使榜单不可比 | judge 版本 + prompt hash 入 manifest；官方榜双 judge 报一致率 |
| judge 自我偏好 | judge 与被评模型异家族 |
| 长度偏差 | W9 注水攻击 + 报修前/修后分开 |
| 模型过拟合基准 | 定期换种子 + held-out 探针池（不进 prompt） |
| 成本失控 | 合成宇宙 + 短章 + 分层评测（机械筛完语义只跑可疑段）；judge 输出短，成本 ≪ 生成 |

## 九、测试策略总纲

- **零 LLM**：`contracts` / `mechanical` / `state` / `probes` / `report` / `attacks` 全纯函数，fixture 驱动，入 CI
- **可注入**：`semantic` 走 `JudgeBackend` 协议；测试用 `FixtureJudge`（读录制 JSON）
- **端到端**：一次真实运行录制为 fixture，CI 回放
- **判定器发版准入**：人工标注 50 条 → Kappa 达标才发版
