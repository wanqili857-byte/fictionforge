# 框架设计全景（2026-08-28）

> 框架级设计原则，落地依据。实现细节见 ARCHITECTURE.md，版本计划见 VERSION_PLAN.md。
> 本文档记「为什么与是什么」，不记「怎么做」。

## 缘起

番茄打击批量低质 AI 文 → 框架定位从「日更流水线」转「精品生产线」：
**AI 草稿 + 人工修订 + 修订回灌**。框架管的不是产量，是一致性、上下文、信息差、
以及把作者每次修订变成可积累的品味资产。

## 五层

```
【意图层】   作者独占：真相、主题、口味
             世界观 / 真相表 / 人设基底 / 写作法则
                │
【剧本层】   大剧本（幕 A-D）—— 作者骨架，LLM 只扩写
             幕级子世界观 = 视角过滤器（该幕可知的世界）
             幕级情绪曲线（压/爽/反转的节奏）
             幕级人物弧（人物状态机以幕为步长，事件为转移条件）
                │
【章节层】   spec（作者写）—— 节/场景/张力方向 + 章末钩子（从幕曲线取）
                │
【执行层】   LLM 生成草稿 → AI 事后标注修订原因
                │
【定稿层】   canon —— 人工修订晋升，唯一真源
```

下行循环（生产）：意图 → 剧本 → 幕 → 章 → 稿。每往下一层，信息过滤一次
（真相 → 该幕可知 → 该章可见 → 该节展开）。

上行循环（学习）：定稿 → 差异注记（章级，回 spec/剧本）→ 幕边界修订检查点
（回大剧本）→ 修订 diff + 标签蒸馏 → 判例库（回意图层）。

## 权责三分

- **作者** = 意图与最终文本（骨架、拍板、canon）
- **框架** = 一致性（状态、上下文、信息过滤、预算）
- **LLM** = 执行（扩写、起草、标注）

框架从不当作者，LLM 从不拍板，作者不抄状态表。

## 五铁律

1. **canon 唯一真源** —— 状态、上下文、回灌全部从定稿派生，不从 AI 草稿。
   生成管线永不覆盖 canon。
2. **例对 > 规则句** —— 一切品味资产以例子形态存在。prompt 里任何句子都是
   例子，模型好坏照抄；规则句、坏例、meta 读者行都是隐式教唆。
3. **给内容 > 锁语法** —— 素材（形貌/声带/氛围）越多越生动；语法锁每条都在
   删表达手段，砍到必要。表演指令是隐性锁语法。
4. **知识边界** —— 每个生成调用都有知识边界。真相表（世界级）、幕过滤
   （剧情级）、spec（章级）是同一原则的三个粒度。信息差是结构性的，不是碰运气。
5. **配额经济** —— prompt 是稀缺资源，每种内容价格不同：

   | 内容 | 每字产出 | 记账 |
   |---|---|---|
   | 素材/好例 | 高 | 预算最大桶 |
   | 目标/走向 | 中 | 中桶 |
   | 锁语法 | 低 | 严格小桶 |
   | 规则句/坏例/meta | 负（产出服从不产人味） | 禁入 |

   总量硬顶（实测 ~2300 字为线）；超了不是加，是换（新例进，旧例挤）；
   默认沉默（没写的都允许，只写想要的样子）；挑选权下放（给素材+目标，
   表演交给模型）。回灌资产只增 → 预算逼蒸馏 → 合并旧例、挤掉低产例
   → prompt 保持精瘦。

## bible 分法

```
bible/
  宪法/    世界观、真相表、人设基底、写作法则 —— 作者写，稳定
  判例/    素材库 —— 修订回灌积累（只存好例：作者人改后的句子），有配额，演化
```

同一 prompt 注入，分开维护、分开配额。判例库是「框架越用越懂作者」的具象。
**判例只收好例（人改句）**——v5 教训：AI 原句是坏例，进 prompt 会被模型照样抄；
AI 原句对（旧→新）只留在 `chapters/_revisions/` 供作者人审，不进 prompt。

## 节拍分工

- **幕级**（大剧本）：本幕读者情绪走向——压/爽/反转节奏，哪几章是高点
- **章级**（spec 落地时）：钩子挂哪节末尾、什么类型——作者从幕曲线里取

同一资产两个粒度：曲线管幕的味，钩子管章的勾。
